Build Plan · Rust + Ratatui

Keyforge — a terminal typing dojo

A Monkeytype-style typing trainer that lives in your terminal — built in Rust with Ratatui, while you learn Rust. Practice prose, language keywords (C, C++, Rust, Python…), and real editor/multiplexer muscle memory (Vim, Neovim, Tmux, Helix), then watch your keyboard heatmap and WPM curve improve session over session.

rust 2021 edition ratatui + crossterm config via TOML 8-week sprint plan 4 built-in themes
What this is

One project, two curricula

Every sprint pairs a slice of The Rust Programming Language book with a matching slice of Keyforge. You never learn a Rust concept in the abstract — the same day you read about ownership, you use it to model the typing buffer.

⌨ Core loop

Monkeytype-like test: live word coloring, WPM/accuracy timer, restart-on-tab, results screen.

🗂 Custom sources

Plain text, quotes, or language keyword banks — C, C++, Rust, Python, Go — plus your own word files.

🧠 Keybinding drills

Vim motions, Neovim leader sequences, Tmux prefixes, Helix keymaps — scored like a typing test.

🎨 Theming

Cursor Dark Midnight, Nord, Dracula, Solarized Light — swappable at runtime, defined in TOML.

🔥 Keyboard heatmap

Per-key press count, error rate and latency, rendered as a colored QWERTY layout in-terminal.

📈 Progress metrics

WPM history sparkline, consistency, error breakdown, session log — all persisted locally.

Cadence

The rhythm of a sprint week

Day Rust study (0.5h) Project work (1h) Source
Day 1 Read + run examples for the week's chapter(s) Implement the core data/logic piece the chapter unlocks The Rust Book
Day 2 Rewrite examples from scratch, no copy-paste Wire that logic into the Ratatui UI The Rust Book + rustlings-style drills
Day 3 Skim "further reading" / doc.rs for crates used Polish, test, commit; write the week's milestone note docs.rs / crate READMEs

Total: 3 sessions × 1.5h = 4.5h/week — 1.5h Rust theory, 3h hands-on build. Open the Roadmap tab for all 8 weeks.

Product spec

Feature-by-feature walkthrough

Each feature below shows a realistic mockup of the finished screen plus an expandable implementation note.

⌨

Core typing test

01

The Monkeytype-style heart of the app: words stream in, you type, correct characters go green, mistakes go red with the original character still visible underneath, and a live WPM/timer readout runs in the header. Supports words, time, and zen (no target, just flow) modes.

keyforge · mode: time 30s
┌─ keyforge ─────────────────────────────── 00:18 72wpm ─┐
              ��� │
              │ fn main() { let mut app = App::new(); app.run() │
              │ while let Some(ev) = poll_event() { } │
              │ │
              │ esc restart tab menu ctrl+t theme │
              └──────────────────────────────────────────────────────┘
Implementation notes
  • State machine: Idle → Running(Instant) → Finished(Summary), driven from Week 3.
  • Per-second WPM bucketing feeds the results sparkline directly — no post-hoc recompute.
  • Rendering diffing kept simple: re-render the whole frame at ~30fps via ratatui's immediate-mode model; no manual dirty-rect tracking needed.
  • Word wrapping respects terminal width using unicode-width so wide/CJK test text (optional) doesn't misalign the cursor.
🗂

Custom text & word sources

02

Beyond the default English word list: point Keyforge at any .txt file for custom passages, drop in a folder of quote files, or toggle punctuation/number injection on top of any source.

source picker
┌─ choose source ────────────────────────────────────────┐
              │ > builtin — english 1k │
              │ custom file — ~/texts/monkeytype_quotes.txt │
              │ language keywords — [ rust c cpp python go ] │
              │ [x] punctuation [ ] numbers │
              └─────────────────────────────────────────────────────┘
Implementation notes
  • trait WordSource unifies builtin/file/language sources (Week 5) — the UI never special-cases which one is active.
  • Custom files are read once, tokenized, and shuffled with rand::seq::SliceRandom; huge files stream in 2000-word windows to stay memory-light.
  • Punctuation/number injection is a decorator over any WordSource, not baked into each source — composable via PunctuatedSource::wrap(inner).
💻

Language keyword practice

03

Curated keyword/symbol banks per language — Rust, C, C++, Python, Go to start — so you drill the exact tokens and punctuation density (->, ::, {}, &mut) that make real code typing awkward, without needing a real compiling snippet.

language: rust
┌─ mode: language / rust ────────────────────────────────┐
              │ impl<T: Clone> From<Vec<T>> for Wrapper where Self: Sized │
              │ pub fn try_into(&self) -> Result<Self, Error> {
                } │
              └───────────────────────────────────────────────────────┘
Implementation notes
  • Keyword banks live as plain TOML lists under assets/languages/*.toml — editable without recompiling.
  • An optional "snippet mode" samples real short functions (checked into assets/snippets/) instead of shuffled tokens, for more realistic muscle memory.
  • Symbol-heavy tokens are weighted slightly higher in sampling so operators like ::, =>, &mut show up often enough to matter.
🧠

Keybinding drill mode

04

The extension beyond plain typing: practice the actual chord sequences for Vim motions/text-objects, Neovim leader-key mappings, Tmux prefix commands, and Helix keymaps — scored on chord accuracy and hesitation time, not characters-per-minute.

keybindings: tmux
┌─ drill: tmux / prefixes ───────────────────────────────┐
              │ next C-b " split pane horizontally │
              │ history ✓ C-b % ✓ C-b z ✗ C-b [ (too slow) │
              │ set: tmux · nvim-leader · vim-motions · helix │
              └─────────────────────────────────────────────────────┘
Implementation notes
  • Each drill set is a data file (keymaps/vim.toml etc.) mapping a human label to an ordered Vec<KeyChord> — new keymaps (e.g. Emacs, Zellij) are just new TOML files.
  • Timing model: hesitation = time between chord shown and first correct key; chord time = first-to-last key of that chord. Both feed the heatmap in Feature 6.
  • A chord is scored correct only if every key in the sequence matches in order — partial credit is intentionally not given, matching how real muscle memory either fires or doesn't.
🎨

Theme engine

05

Four built-in themes — Cursor Dark Midnight, Nord, Dracula, Solarized Light — each a plain TOML file of 13 named colors, hot-swappable with Ctrl+T or set permanently in config.toml. Drop a new .toml into the themes folder and it shows up in the picker automatically.

theme picker
┌─ theme ────────────────────────────────────────────────┐
              │ > dracula ●●●● │
              │ nord ●●●● │
              │ cursor-dark-midnight ●●●● │
              │ solarized-light ●●●● │
              └─────────────────────────────────────────────────────┘
Implementation notes
  • Theme struct derives serde::Deserialize directly from TOML — no manual parsing.
  • Colors stored as hex strings, converted once at load time into ratatui::style::Color::Rgb(r,g,b).
  • A ThemeRegistry scans ~/.config/keyforge/themes/*.toml at startup, falling back to 4 themes embedded in the binary via include_str! if the folder is empty.
🔥

Keyboard heatmap

06

A full QWERTY layout rendered in the terminal, colored by whichever metric you're inspecting: press frequency, error rate, or average latency. Great for spotting which finger/row is actually slowing you down.

heatmap · metric: latency
┌─ keyboard heatmap ── metric: [latency] freq errors ─────┐
              │ QWERTYUIOP │
              │ ASDFGHJKL │
              │ ZXCVBNM │
              │ green <80ms yellow 80-160ms red >160ms │
              └─────────────────────────────────────────────────────┘
Implementation notes
  • Layout is a static coordinate table (KeyCode → (row, col)) for a US-QWERTY grid; alternate layouts (Colemak, Dvorak) are a config-swappable table, not a code change.
  • Colors are computed on a continuous gradient (green→yellow→red) rather than 3 hard buckets, so the demo buckets above are a simplification of a smooth scale.
  • Backed by the same HashMap<KeyCode, KeyStat> that also feeds keybinding-drill scoring — one source of truth.
📈

Progress & metrics dashboard

07

Every session is appended to a local history file. The dashboard surfaces WPM trend, accuracy trend, a consistency score (lower variance = steadier typing), and a scrollable session log.

progress dashboard
┌─ progress ── last 14 days ─────────────────────────────┐
              │ wpm ▂▃▃▄▅▄▆▇▆▇█▇█▇ avg 68 best 81 │
              │ accuracy ▇▇▇▆▇█▇▇█▇▇█▇▇ avg 96.4% │
              │ consistency ▄▅▄▅▆▅▆▆▇▆▇▇▇▇ σ 8.2ms ↓ improving │
              │ sessions 128 total · 4.2h practiced │
              └─────────────────────────────────────────────────────┘
Implementation notes
  • History persists as newline-delimited JSON (~/.local/share/keyforge/history.jsonl) — append-only, trivially grep-able, no database dependency.
  • Consistency = standard deviation of per-keystroke interval, normalized against that session's mean interval — a common Monkeytype-style metric.
  • ratatui::widgets::Sparkline renders all three trend lines; a --export csv flag can dump history for external analysis.
⚙

TOML configuration

08

Everything user-facing — mode, source, theme, keybinding set, display toggles — lives in one config.toml, auto-created on first run and hand-editable. See the full example in the Themes & Config tab.

Implementation notes
  • Config derives Default so any missing/invalid field falls back gracefully instead of crashing on a hand-edited typo.
  • Config path resolution follows XDG conventions via the dirs crate: ~/.config/keyforge/config.toml on Linux, matching platform conventions on macOS/Windows.
  • CLI flags (via clap) override config file values for one-off runs, e.g. keyforge --mode zen --theme nord.
