typetui 

A monkeytype-style typing trainer that lives in your terminal — built as the vehicle for learning Rust. Practice English words, language-specific keyword sets (Rust/C/C++/Python), and real editor & multiplexer muscle memory (Vim, tmux), while tracking WPM, accuracy, and per-key heat over time. Every colorscheme in the switcher above is a real one you'll ship — this page is themed by the same tokens the TUI will use.

# 12-week sprint roadmap

Each sprint is one calendar week. Work happens in 3 sessions (e.g. Mon / Wed / Fri), 3 hours each — 1 hour of focused Rust learning + practice (following The Rust Book), then 2 hours applying it directly to typetui. Click a week to expand the day-by-day plan. Rust concepts are sequenced so the book chapter you read on Monday is the exact thing you need to implement by Friday.

# Project architecture

A single-binary Rust crate, organized so each module maps to one concern. State lives in one App struct; everything else is a pure function of it.

state ownership

App owns everything: the current TestSession (target text, typed buffer, char-by-char correctness), Config (loaded once from TOML at startup, hot-reloadable via a filesystem watcher channel), StatsStore (append-only run history persisted to ~/.local/share/typetui/history.jsonl), and Theme (derived from config, swappable at runtime the same way the picker above works). Rendering (ui::draw) takes &App and never mutates it — all mutation happens in update() in response to a crossterm::event::Event. This keeps the borrow checker happy and makes the whole render path trivially testable: feed it an App, snapshot the buffer.

# Configuration — ~/.config/typetui/config.toml

Parsed with serde + toml into a typed Config struct at startup, with #[serde(default)] on every field so a partial or missing file still works. CLI flags (via clap) override individual fields for one-off runs, e.g. typetui --mode words --lang cpp --time 30.
